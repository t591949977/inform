Серверные процедура подразделяются на серверные процедуры с передачей контекста и без передачи контекста. Под передачей контекста подразумевается синхронизации формы на сервере и на клиенте. Это процесс довольно медленный, поэтому часто выбирают вариант серверной функции без контекста, в которую данные с формы передаются не все, а лишь те которые непосредственно нужны. Эти данные передаются в виде параметров серверной процедуры. Изменение конфигурации на работающей базе у клиента производить запрещено. У конфигурации находящихся у клиентов должна быть заблокирована возможность изменения объектов. Для того чтобы стать поставщиком конфигурации необходимо настроить свойства конфигурации. Для этого в конфигураторе заходим в его свойства и на вкладку Основные задаем имя конфигурации. Переходим на вкладку Разработка, заполняем поля Поставщик, Версия и Адрес каталога обновления. Адрес каталога обновления это то где будет по умолчанию система искать файлы обновления, возможно это будет адрес FTP сервера или адрес локального каталога предприятия или адрес каталога на компьютере пользователя куда он будет складывать присланные обновления. Для начала необходимо создать первый релиз системы для поставки конфигурации пользователю. Для этого в основном меню выбираем Конфигурация/Поставка конфигурации/Создать файлы поставки и обновления конфигурации. Необходимо оставить только птичку Создать файл поставки и нажав кнопку Каталог файлов поставки выбрать каталог, куда будут сохраняться файлы. Жмем кнопку Выполнить, создаться файл в формате cf (это формат полной конфигурации без данных). Пользователь должен создать пустую базу. Затем открыв ее в конфигураторе выполнить загрузку конфигурации, для этого в главном меню выбираем Конфигурация/Загрузить конфигурацию из файла. В дальнейшем пользователю нужно передовать не целиком конфигурацию, а лишь внесенные изменения. Для этого в свойствах конфигурации в разделе Разработка изменить номер версии. Выбираем в главном меню Конфигурация/Поставка конфигурации/Создать файлы поставки и обновления конфигурации. Необходимо оставить только птичку Создать файл обновления конфигурации. Жмем на кнопку Добавить из предыдущей версии или кнопку добавить и выбираем файл конфигурации для обновления. Создаться файл обновления в формате cfu. Этот файл позволит пользователю обновить конфигурацию, но не позволит ему создать конфигурацию с нуля. Пользователь должен выбрать в главном меню Конфигурация/Поддержка/Обновить конфигурацию и выбрать файл обновления. Но использовать данный метод для пользователя не удобно, поэтому предпочтительно создавать комплект поставки. По сути эта та же конфигурация, но упакованная в ехе файл, при запуске которого будет запускаться мастер. Выбираем в главном меню Конфигурация/Поставка конфигурации/Комплект поставки. При запуске ЕХЕ файла у пользователя, в каталог шаблонов конфигураций включиться наш шаблон на основе которого пользователь может создать конфигурацию. Для этого в основном меню выбираем Жмем на кнопку Создать комплект, выбираем каталог сохранения описание комплекта и самого комплекта. Теперь пользователь не создавая пустой конфигурации, просто запускает файл Setup.exe, выбирает этот же каталог с поставкой и доводит процесс до конца. Затем запускает 1С, жмет кнопку добавить, выбирает Создать новую информационную базу, Создать информационную базу из шаблона. Выбираем требуемый шаблон. Все база у пользователя создана одновременно с конфигурацией. Теперь для создания обновления, необходимо в свойстве конфигурации изменить номер конфигурации. Затем, создаем комплект поставки (как раньше). Для обновления версии пользователю нужно войти в конфигуратор и выбрать Конфигурация/Поддержка/Обновить конфигурацию. Выбираем требуемое обновление и т.д. Управлять Шаблонами создания конфигурации можно через меню. Существует еще один способ обновления для пользователя, это создание пакетного запуска программы. Но этот способ не будем рассматривать. Если пользователь запустит конфигуратор, то все объекты будут заблокированы от изменения. Замочки указывают, что у клиента конфигурация находиться на поддержке. Для создания обновления, в этом случае, Но пользователь может включить возможность редактирования конфигурации, для этого в главном меню Конфигурация/Поддержка/Настройка поддержки, выводиться окно в котором нужно нажать кнопку Включить возможность изменения. Замочки исчезнут, но кубики останутся, это указывает, что конфигурация остается на поддержке, но включена возможность изменения объектов. Теперь если в этой конфигурации внести изменения, то система будет запоминать какие изменения внесены. Теперь при приходе очередного обновления, система автоматически обновляться не будет, а предложит принятия решения пользователю. Объекты измененные в конфигурации у пользователя не будут отмечены птичкой и следовательно обновлению не подлежат. Если пользователь хочет отказаться от внесенных им изменений, то он должен поставить птички. Но вернуться к автоматическому методу уже будет невозможно. Включение возможности редактирования увеличивает размер занимаемой базой, так как создается новый файл с методаными. Если пользователь хочет снять с поддержки конфигурацию, то в окне Настройка поддержки выбирается Снять с поддержки. Теперь обновление работать не будет. И возможен только режим объединения с другой конфигурацией. Где на свой риск отмечаете объекты подлежащие объединению.
