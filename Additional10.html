📋 Регламентные задания в 1С 8.3

Определение

Регламентное задание — это прикладной объект метаданных, предназначенный для выполнения определённых действий автоматически, по заданному расписанию, без участия пользователя. Регламентные задания используются, когда необходимо выполнять периодические или однократные действия в соответствии с расписанием. Регламентные задания являются неотъемлемой частью конкретного прикладного решения и описываются на этапе конфигурирования. В конфигурации ряд действий выполняется по определённому расписанию регламентными заданиями, которые могут создаваться на основе предопределённых шаблонов.

Ключевое отличие регламентного задания от фонового: регламентное задание описывает что и когда нужно выполнить, а фоновое задание — это непосредственное выполнение кода в отдельном сеансе. В соответствии с расписанием регламентное задание порождает фоновое задание, которое и выполняет заданные действия.

Когда использовать регламентные задания: когда нужно автоматизировать рутинные операции — загрузку курсов валют, обновление индексов, рассылку отчётов, обмен данными с другими системами, пересчёт итогов регистров. При этом если регламентные задания не требуется добавлять или удалять в зависимости от действий пользователя или логики конфигурации, следует использовать предопределённые регламентные задания.

Свойства регламентного задания в конфигураторе

При создании регламентного задания в дереве конфигурации заполняются следующие свойства:

Имя — идентификатор для обращения из кода. Например: ОбновлениеИндекса, ЗагрузкаКурсовВалют.

Имя метода — процедура или функция, которая будет выполняться при срабатывании задания. Метод должен находиться в общем модуле, который доступен на сервере. Это обязательное требование — регламентные задания выполняются только на сервере.

Использование — флаг, определяющий, будет ли задание выполняться автоматически. Если флаг снят, задание не запускается по расписанию, но может быть выполнено вручную.

Предопределённое — флаг, указывающий, что задание создаётся автоматически при обновлении конфигурации. Предопределённые регламентные задания не отличаются от обычных, за исключением того, что их нельзя явно создавать и удалять — они автоматически создаются в информационной базе при обновлении конфигурации и автоматически удаляются, если флаг предопределённости снят.

Расписание — настройка периодичности выполнения задания. Расписание можно задать как на этапе конфигурирования, так и на этапе выполнения в режиме 1С:Предприятие.

Количество перезапусков — число попыток перезапуска задания при аварийном завершении. Используется, когда метод задания должен быть выполнен обязательно.

Интервал перезапуска — временной интервал между попытками перезапуска при сбое.

Состав и структура расписания

Расписание регламентного задания определяет, когда именно должно срабатывать задание. В диалоге редактирования расписания доступны несколько закладок, позволяющих задать различные виды расписаний.

Общие — задаётся периодичность повторения (например, «Повторять каждые: 1 дн.»), а также дата начала и окончания выполнения.

Дневное — настраивается порядок запуска в течение дня: время начала, время окончания, интервал повторения в секундах.

Недельное — выбираются дни недели, в которые задание должно выполняться.

Месячное — задаётся число месяца или конкретный день недели месяца (например, «вторая среда каждого месяца»).

 

Примеры расписаний:

*Каждый час, только один день: DaysRepeatPeriod = 0, RepeatPeriodInDay = 3600.

*Каждый день один раз: DaysRepeatPeriod = 1.

*Каждую субботу и воскресенье в 9:00: WeekDays = 6, 7, BeginTime = 09.00.

*Последнее число каждого месяца в 9:00: DayInMonth = -1.

*Вторая среда каждого месяца в 9:00: WeekDayInMonth = 2, WeekDays = 3.

 

В нижней части диалога отображается итоговый результат всех установок — созданное расписание в текстовом виде.

Особенности выполнения в клиент-серверном и файловом вариантах

Запуск и исполнение регламентных заданий в клиент-серверном и файловом вариантах работы 1С:Предприятия существенно отличаются.

В клиент-серверном варианте запуск регламентных заданий по расписанию осуществляет менеджер кластера серверов 1С:Предприятия. Даже если с информационной базой не установлено ни одного клиентского соединения, регламентные задания будут выполняться — при условии, что они не запрещены для конкретной информационной базы. Несколько различных заданий могут выполняться параллельно.

В файловом варианте для автоматического запуска регламентных заданий необходимо наличие выделенного клиентского соединения, используемого в качестве планировщика заданий. В этом соединении должна быть запущена обработка ожидания, с некоторой периодичностью выполняющая вызов метода ВыполнитьОбработкуЗаданий(). Задания выполняются последовательно, а не параллельно.

Команда «Выполнить сейчас» позволяет выполнить любое регламентное задание либо в текущем сеансе (для файловой информационной базы), либо в фоновом задании на сервере (для серверной информационной базы).

Программная работа с регламентными заданиями

Поиск и создание задания

Для программного управления регламентными заданиями используются два ключевых объекта: РегламентноеЗадание и РасписаниеРегламентногоЗадания. Объект РегламентноеЗадание представляет само задание, а свойство Расписание этого объекта является экземпляром РасписаниеРегламентногоЗадания, которое содержит всю информацию о периодичности выполнения.

Пример поиска задания по имени:

ИмяЗадания = "ОбновлениеЦенНоменклатуры";

РегЗадание = РегламентныеЗадания.НайтиПоИмени(ИмяЗадания);

Если РегЗадание = Неопределено Тогда

Сообщить("Регламентное задание не найдено");

Возврат;

КонецЕсли;

 

Пример поиска по метаданным и создания, если не существует:

МЗ = Метаданные.РегламентныеЗадания.ОбновлениеЦенНоменклатуры;

Задания = РегламентныеЗадания.ПолучитьРегламентныеЗадания(МЗ);

Если Задания.Количество() > 0 Тогда

Задание = Задания[0];

Иначе

Задание = РегламентныеЗадания.СоздатьРегламентноеЗадание(МЗ);

КонецЕсли;

 

Настройка расписания программно

Часто возникает задача изменить расписание задания без изменения конфигурации. Для этого создаётся новый объект РасписаниеРегламентногоЗадания и настраиваются его свойства.

Пример установки интервала повтора 15 минут:

НовоеРасписание = Новый РасписаниеРегламентногоЗадания;

// Начало и конец интервала (дата обычно не играет роли при установке интервала)

НовоеРасписание.Начало = '00010101000000';

НовоеРасписание.Конец = '00010101000000';

// Интервал повтора в секундах (15 минут = 900 секунд)

НовоеРасписание.ПериодПовтораВТечениеДня = 900;

// Отключаем использование дней недели, месяцев, годовых дат

НовоеРасписание.ИспользованиеДнейНедели = Ложь;

НовоеРасписание.ИспользованиеМесяцев = Ложь;

НовоеРасписание.ИспользованиеГодовыхДаты = Ложь;

// Присваиваем расписание и записываем

Задание.Расписание = НовоеРасписание;

Задание.Использование = Истина;

Задание.Записать();

 

Все изменения расписания не вступят в силу до тех пор, пока не будет вызван метод Записать() у объекта РегламентноеЗадание.

Клиент vs Сервер: особенности работы

Регламентные задания выполняются только на сервере. Метод, указанный в задании, должен находиться в общем модуле, доступном на сервере. Это связано с тем, что регламентные задания порождают фоновые задания, которые выполняются в отдельном серверном сеансе.

Программное управление регламентными заданиями (создание, изменение расписания, запуск) также выполняется на сервере. На клиенте можно только вызывать серверные процедуры, которые, в свою очередь, работают с регламентными заданиями.

Пример запуска регламентного задания вручную (на сервере):

&НаСервере

Процедура ЗапуститьРегламентноеЗадание()

ИмяМетода = Метаданные.РегламентныеЗадания.ОчисткаУстаревшихВерсийОбъектов.ИмяМетода;

// Проверка, выполняется ли фоновое задание

Отбор = Новый Структура;

Отбор.Вставить("ИмяМетода", ИмяМетода);

Отбор.Вставить("Состояние", СостояниеФоновогоЗадания.Активно);

ФоновыеЗаданияОчистки = ФоновыеЗадания.ПолучитьФоновыеЗадания(Отбор);

Если ФоновыеЗаданияОчистки.Количество() = 0 Тогда

ФоновыеЗадания.Выполнить(ИмяМетода);

КонецЕсли;

КонецПроцедуры

Этот пример показывает, как можно предоставить пользователям альтернативную возможность выполнения регламентного задания вручную. Работа системы не должна зависеть от автоматического выполнения регламентных заданий, поэтому рекомендуется предусматривать такую возможность.

Управление регламентными заданиями в интерфейсе

Настройка регламентных заданий выполняется в форме, доступной по ссылке: «НСИ и администрирование» — «Администрирование» — «Поддержка и обслуживание» — «Регламентные операции» — «Регламентные и фоновые задания».

На закладке «Регламентные задания» содержится список заданий. В списке, кроме наименования, отображается состояние исполнения и дата окончания последнего фонового задания. Список можно расширять, добавляя регламентные задания с использованием предопределённых шаблонов. \

Для каждого задания может быть задано расписание автоматического запуска. Можно создать несколько экземпляров одного регламентного задания с разными расписаниями.

На закладке «Фоновые задания» можно проконтролировать выполнение фоновых заданий. Для этого настраивается отбор фоновых заданий по регламентному заданию, периоду, состоянию. Отбор производится только по команде «Обновить».

Ограничения и рекомендации

Ограничения в модели сервиса (1cFresh): в прикладных решениях, ориентированных на работу в модели сервиса, не должно быть регламентных заданий, которые включены в состав любого из разделителей. Это связано с тем, что при большом количестве областей данных разделённые регламентные задания могут вызвать перегрузку рабочих процессов и серьёзно затруднить работу пользователей. Для регулярного выполнения кода в таких приложениях необходимо использовать очередь заданий.

Рекомендации по периодичности: при разработке регламентных заданий необходимо выбирать время и интервал запуска, исходя из прикладного назначения. Частое выполнение заданий может негативно влиять на производительность сервера.

Ни в каких случаях не следует задавать периодичность выполнения регламентных заданий меньше одной минуты. Для большинства заданий нормальным является интервал выполнения в один день. Исключения могут составлять случаи, когда критичным является частое выполнение заданий с прикладной точки зрения. Ресурсоёмкие регламентные операции необходимо по возможности переносить на время минимальной загрузки сервера — в нерабочее время или на выходные дни.

Управление использованием: недопустимо выполнять регламентные задания, если соответствующая им функциональность отключена в программе. Иначе задания будут приводить к запускам сеансов, занимая вычислительные ресурсы сервера. Для этого необходимо программно управлять признаком Использование предопределённого регламентного задания в зависимости от включённых функциональных опций.

Итоговая сводка

Регламентное задание — объект метаданных для автоматического выполнения кода по расписанию без участия пользователя.

Состав: имя, метод (процедура в общем серверном модуле), использование, предопределённость, расписание, количество и интервал перезапусков.

Расписание настраивается через диалог с закладками: Общие, Дневное, Недельное, Месячное. Поддерживаются однократные и периодические расписания.

Клиент-серверный вариант: запуск осуществляет планировщик кластера, задания выполняются параллельно, работают без активных клиентских сеансов.

Файловый вариант: требуется выделенный клиентский сеанс-планировщик, задания выполняются последовательно.

Программное управление: поиск через РегламентныеЗадания.НайтиПоИмени() или ПолучитьРегламентныеЗадания(), создание через СоздатьРегламентноеЗадание(), настройка расписания через объект РасписаниеРегламентногоЗадания, сохранение через Записать().

Ключевое правило: регламентные задания выполняются только на сервере. Метод задания должен быть в общем модуле, доступном на сервере.
📋 Фоновое Задание в 1С 8.3

Определение

Фоновое Задание — это объект встроенного языка, предназначенный для выполнения прикладных задач асинхронно, то есть незаметно для пользователя и параллельно другим процессам . В отличие от регламентного задания, которое описывает что и когда нужно выполнить, фоновое задание представляет собой непосредственное выполнение кода в отдельном сеансе. Ключевое преимущество фоновых заданий заключается в том, что выполнение ресурсоёмких процедур не блокирует интерфейс и не мешает сотрудникам вносить или редактировать данные . Пользователь продолжает работать, пока система в фоне выполняет сложные вычисления, обработку данных или обмен информацией. Фоновые задания могут порождать дочерние фоновые задания — например, для распараллеливания сложных вычислений по различным рабочим серверам кластера в клиент-серверном варианте работы .

Связь с регламентными заданиями: регламентное задание обязательно инициирует запуск фонового задания . Планировщик заданий (job scheduler) проверяет расписание регламентного задания и, если наступает время выполнения, создаёт фоновое задание, которое и выполняет реальную работу .

Когда использовать фоновые задания: когда нужно выполнить длительную операцию, не заставляя пользователя ждать. Например, формирование сложного отчёта, массовая обработка документов, загрузка данных из внешних источников, обмен с другими системами.

Свойства фонового задания

Фоновое задание как объект встроенного языка имеет следующие ключевые свойства:

Имя метода — процедура или функция, которая будет выполняться. Метод должен находиться в общем модуле, доступном на сервере . Имя метода состоит из имени модуля и имени процедуры/функции.

Ключ — прикладной идентификатор, задаваемый разработчиком. Служит для группировки запущенных фоновых заданий по определённому прикладному признаку . Уникальность ключа проверяется отдельно для фоновых заданий, запущенных программно, и для фоновых заданий, порождённых регламентными заданиями .

Параметры — значения, передаваемые в метод задания. Могут быть любыми прикладными значениями.

 

Фоновое задание выполняется от имени пользователя, который его создал . Это важно учитывать при настройке прав доступа и разграничении данных.

Особенности свойства «Ключ»

Свойство «Ключ» заслуживает отдельного рассмотрения, поскольку его поведение неочевидно.

В синтаксис-помощнике сказано, что невозможно создать два фоновых задания с одинаковым именем метода и одинаковым непустым ключом. Однако на практике контроль уникальности работает раздельно для двух категорий заданий .

Программно запущенные фоновые задания: если в клиент-серверной базе попытаться запустить второе задание с тем же методом и ключом, возникнет исключение «Задание с таким значением ключа уже выполняется» .

Фоновые задания, порождённые регламентным заданием: уникальность ключа проверяется в пределах объекта метаданных регламентного задания . При этом возможна ситуация, когда регламентное задание запустило фоновое задание с методом «Модуль.Метод» и ключом «Ключ», а затем программный запуск создал ещё одно задание с тем же методом и ключом — ошибки не возникнет, и оба задания будут работать .

В файловом варианте контроль уникальности ключа может работать иначе. На платформе 8.3.25 было отмечено, что в файловой базе два одинаковых фоновых задания запускаются без ошибок .

Таким образом, ключ для программных заданий и ключ для регламентных заданий имеют разное назначение и контролируются независимо .

Программная работа с фоновыми заданиями

Запуск фонового задания

Основной метод для программного запуска — ФоновыеЗадания.Выполнить(). Он принимает имя метода, параметры, ключ и наименование задания .

// Простой запуск фонового задания

ФоновыеЗадания.Выполнить("ОбщегоНазначения.ВыполнитьОбработку", Параметры, "КлючОбработки", "Обработка данных");

 

Ожидание завершения

Для ожидания завершения фонового задания используется метод Ждать() или ЖдатьЗавершения():

Задание = ФоновыеЗадания.Выполнить("МойМодуль.ДлительнаяОперация", Параметры, "УникальныйКлюч", "Длительная операция");

Задание.ЖдатьЗавершения();

 

Поиск фоновых заданий

Менеджер фоновых заданий позволяет искать задания по имени, ключу, состоянию :

Проверка состояния

Фоновое задание может находиться в одном из состояний: «Активно», «Завершено», «Отменено», «Ошибка». Свойство Состояние возвращает текущее состояние .

 

Мониторинг и управление

Механизм заданий имеет развитые средства мониторинга :

Журнал регистрации — при запуске фонового задания записывается событие начала выполнения, по окончании — событие успешного завершения или описание ошибки. В журнал можно добавлять диагностические сообщения для лучшего понимания происходящего в задании .

Консоль заданий — внешняя обработка, позволяющая управлять заданиями интерактивно. Позволяет создавать, удалять, изменять регламентные задания, выполнять, отменять и мониторить фоновые задания .

Программные средства — объекты МенеджерФоновыхЗаданий и МенеджерРегламентныхЗаданий для поиска, отмены и ожидания завершения заданий .

Особенности выполнения в разных окружениях

Клиент-серверный вариант

Запуск регламентных заданий осуществляется автоматически планировщиком кластера серверов. Фоновые задания выполняются параллельно, распределяясь по рабочим процессам кластера . Для выполнения фоновых заданий не требуется активных клиентских сеансов — достаточно, чтобы работал кластер серверов .

Файловый вариант

Фоновые задания выполняются последовательно, а не параллельно . Для автоматического запуска регламентных заданий (и порождаемых ими фоновых) необходимо наличие выделенного клиентского соединения, используемого в качестве планировщика заданий . В сеансе, полученном через внешнее соединение, работа фоновых заданий не поддерживается .

Мобильное приложение

В мобильных приложениях фоновые задания выполняются последовательно самим приложением. Выполнение регламентных заданий в мобильной среде не поддерживается .

Работа с расширениями конфигурации

При запуске фонового задания в его сеансе подключаются расширения, которые были подключены в родительском сеансе . Однако можно управлять этим поведением:

* Запуск с расширениями базы данных: метод ConfigurationExtensions.ExecuteBackgroundJobWithDatabaseExtensions() — подключает все расширения, зарегистрированные для текущей информационной базы и текущего набора разделителей .

* Запуск без расширений: метод ConfigurationExtensions.ExecuteBackgroundJobWithoutExtensions() — запускает фоновое задание без каких-либо расширений конфигурации . Это полезно, когда нужно выполнить код «как есть», без влияния расширений.

Блокировка выполнения заданий

Существует возможность заблокировать выполнение регламентных заданий информационной базы. Это делается через консоль кластера серверов или программно. Блокировка установки соединения также запрещает запуск регламентных заданий .

В свойствах информационной базы в консоли администрирования сервера есть опция «Блокировка выполнения регламентных заданий». Если она включена, задания не выполняются автоматически, но остаются доступными для ручного запуска .

Итоговая сводка

Фоновое задание — объект встроенного языка для асинхронного выполнения прикладных задач. Не блокирует интерфейс, выполняется от имени создавшего пользователя.

Связь с регламентными заданиями: регламентное задание инициирует фоновое задание, которое выполняет реальную работу.

Свойства: имя метода (процедура в общем серверном модуле), ключ (для группировки заданий), параметры.

Ключ: контроль уникальности работает раздельно для программных и регламентных заданий. В файловом варианте поведение может отличаться.

Основные методы: ФоновыеЗадания.Выполнить() — запуск; Задание.ЖдатьЗавершения() — ожидание; Задание.Отменить() — отмена; ФоновыеЗадания.ПолучитьФоновыеЗадания() — поиск.

Мониторинг: журнал регистрации, консоль заданий, программные средства управления.

Особенности окружений: клиент-серверный вариант — параллельное выполнение, не зависит от клиентских сеансов; файловый вариант — последовательное выполнение, требуется выделенный сеанс-планировщик; мобильное приложение — только фоновые задания, без регламентных.
